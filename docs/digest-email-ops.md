# 決算定期便のメール配信 運用手順書（JCE-086）

## 位置づけ

決算定期便（/digest）のメール版。毎週、登録された読者に今週の開示を届ける。目的はニュースの速報ではなく、学んだ読み方を実際の決算で試す訓練の実践——「分析訓練環境」の導線（無料体験 → メール等の直接接点 → 有料）の一部である。

**現状は下準備まで**。下書きの生成はできるが、送信の仕組みはまだ無い。宛先リストは空である。送信は、下書きの確認を経て Gmail コネクタ経由で人が行う。自動送信はしない。

## 配信タイミング（推奨）

- **毎週月曜 07:30 JST**。前週の月曜〜日曜の開示をまとめて送る。週が閉じてから送るため、件数が確定する。
- 月曜が祝日の場合も同じ時刻で送る（開示の有無は下書きの件数で確認する）。
- **最終決定は未定**。曜日・時刻の確定は、βの運用が始まってから利用者の反応を見て決める。

## 実行手順

1. 下書きを生成する（送信はしない）。

   ```sh
   node scripts/digest/send-weekly-digest.mjs
   ```

   既定では公開中の `https://kigyo-hyakka.com/updates.json`（/digest と同じ生成元）から今週分を読み、`scripts/digest/drafts/<今日>-digest-draft.md` に下書きを書く。宛先が空の場合は「送信対象なし」と表示して終了する（下書きは書かれる）。
2. 下書きを確認する（下記「文面の確認手順」）。
3. Gmail コネクタ経由で送信する（現時点では手動。送信元アドレスは未決定のため、送信時に決める）。
4. 送信した下書きファイルは残さない（`scripts/digest/drafts/` は git 管理外。不要になったら消す）。

便利な引数: `--today YYYY-MM-DD`（過去の週の下書きを作り直すとき）、`--updates <ファイルかURL>`（公開前の確認用）、`--recipients <CSV>`、`--out <ディレクトリ>`、`--site <URL>`。

## 文面の確認手順（送る前に必ず行う）

- [ ] 件名の件数と週の範囲が、下書き内の「今週の開示」と一致する。
- [ ] 各開示の要約に対象期間（年度・四半期）が付いている。期間のない数字が無い。
- [ ] 訂正イベントに数字が付いていない（訂正は数字を持たない）。
- [ ] 禁止表現が無い: 株価、PER/PBR/ROE、推奨・買い・売り、目標株価、スコア・格付け。計算値が入っていない。
- [ ] リンクが正しい: 企業ページ、企業レポート（分析5観点）、/learn、/digest、/learn#training-history。
- [ ] 宛先が意図した人数である（重複はスクリプトが除いている）。

## 宛先リストの管理

- 形式: `scripts/digest/recipients.csv`、見出し `email,name,source`、1行1アドレス。`#` で始まる行はコメント。見本は `scripts/digest/recipients.example.csv`。
- **recipients.csv は git 管理外**（.gitignore 済み）。メールアドレスを公開 repo にコミットしないこと。
- 取得の流れ: 募集フォーム（Google フォーム）の回答者がメールアドレスを残す → 運営がそのアドレスを recipients.csv に追加する。フォームの回答がそのまま送信対象になるのではない（同意の範囲はフォームの文面に従う）。
- 重複: スクリプトがメールアドレスで重複を除く（同じ人に2通送らない）。
- 形式の誤り（メールアドレスの形が正しくない行）があるとスクリプトは終了する（推測で直さない）。行番号が表示されるので修正してから再実行する。
- 退会: 現時点では「このメールに返信してお知らせください」と文面に書いてある。届いた停止依頼は、運営が recipients.csv からその行を手動で削除する。JCE-069 のメール通知システムの停止リンクとの統合は未決定（将来の課題）。

## 未決定事項

- 送信元アドレス（どのアドレスから送るか）。
- 配信頻度・曜日の最終決定（推奨は毎週月曜 07:30 JST）。
- 送信手段の自動化（現時点では Gmail コネクタ経由の手動送信のみ。自動化する場合は、下書きの確認を残した設計にすること）。
- 退会リンクの実装（現時点では返信による手動対応）。
- 宛先の取得元が大学アカウントの Google フォームである問題（フォーム自体の移行は別タスク）。

## 禁止事項

- 下書きの確認なしに送らない。
- 宛先リスト（実アドレス）を repo にコミットしない。
- このスクリプトに送信処理を足さない（送る経路は別途決める）。
