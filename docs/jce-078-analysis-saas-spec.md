# JCE-078 仕様案 — 企業分析SaaS（5観点の分析レポートと、分析データの有料化）

状態: 仕様案（2026-11-21、運営者の指示により作成）。決定の記録は docs/decisions.md の JCE-078。
前提: JCE-071（数字付きアラート）、JCE-072（学習コース）、JCE-073（企業レポートと比較）、JCE-075（百科事典のプレミアムゲート全開放）、市場展開ブリーフ（docs/expansion-brief-2026-11-19.md）、BtoB調査（買われているのはデータではなく型別の「判断の代行」、報告書全文PDFの受容価格帯は15,000〜30,000円/件）。
品質方針（2026-11-19）: 質に妥協せず、市場で優位性が取れる水準を作る。

## 1. 狙い

百科事典の資産は2つある。(1) 全上場企業の検証済み財務データ（出典拘束・二重照合を通った印字値）。(2) 経済指標データブック（公的統計の過去10年分、出典管理つき）。どちらも単独では競合がいるが、**企業データと経済環境を同じ出典規律でつないだ分析**は競合がいない。

JCE-075 で百科事典の既存機能は全て無料に開いた。次に有料化するのは、新しく作る「分析データ」の層である。既存の無料範囲を再び閉じることはしない。

## 2. 製品の形

- **企業分析レポート**: 既存の /companies/[company-id]/report を拡張し、5観点の章立てにする。新規の会社比例ルートは作らない（2026-11-21 のデプロイ上限の教訓: レポートルート追加で静的ファイルが 20,000 件の無料枠を超えた。ページ追加は会社数に比例しない形でのみ行う）。
- **無料層**: JCE-073 レポートの現行内容はそのまま無料。分析レポートでも、観点ごとの自社の値と業界中央値は無料で見せる。
- **有料層（SaaS）**: 観点を統合した分析ビュー全体 — 分布の全体像（四分位・順位・パーセンタイル）、複数期の推移、セグメント構成との接続、観点5（外部環境）の指標連携の詳細、印刷・PDF、複数社の分析比較。
- **入口ページ**: /analysis（1ページ）を新設し、分析の考え方と観点の説明、業界別の分析インデックスへの導線にする。会社数に比例しないためファイル数の問題は生じない。

## 3. 5観点と指標の定義

全ての指標に共通する規則（JCE-073 の計算レイヤーの規則を継承する）:

- 値は「計算値」と明記し、計算式を併記する。印字値（有報の記載そのまま）と計算値を混同させない。
- 業界分布は、最新期が自社と400日以内の会社だけで構成する（PEER_WINDOW_DAYS）。分布の母数が5社未満なら分布は出さず、自社の値だけを示す（MIN_DISTRIBUTION）。
- 利益率は同種の利益行同士でのみ分布を作る（profitLineKind: 経常／税引前／営業を混ぜない）。
- 全ての値に sourceIds を持たせ、有報まで辿れるようにする。

| 観点 | 指標 | 計算・出典 | 状態 |
|---|---|---|---|
| 1. 規模と地位 | 売上高の業界内順位・パーセンタイル | 印字値（売上高）。industryPosition で分布化 | 部品あり |
| | 純資産・総資産・従業員数の業界内位置 | 印字値（financials / workforce） | 部品あり |
| 2. 成長 | 売上高の前期比・5期の伸び | 計算値（report-metrics: revenue-growth-1y / 5y） | 既存 |
| | 純利益の前期比 | 計算値（同上） | 既存 |
| | 売上高の推移（指数化系列） | 計算値（industry-figures: revenueIndexSeries、業界系列と重ねる） | 既存 |
| 3. 収益性 | 純利益率 | 計算値（netIncome / revenue） | 既存 |
| | 利益率（同種の利益行） | 計算値（profit / revenue、行の種類を題に明記） | 既存 |
| | 総資産回転率 | 計算値（revenue / totalAssets） | 既存 |
| | 従業員1人あたり売上高・純利益 | 計算値 | 既存 |
| 4. 財務の安定 | 自己資本比率 | 計算値（netAssets / totalAssets） | 既存 |
| | 純資産の推移と増減 | 印字値の系列＋計算値（前期比） | 一部新規 |
| 5. 外部環境との接続 | 海外売上高比率 | 計算値（地域別売上高の海外分 / 全体、JCE-038 の地域別売上） | 既存 |
| | セグメント構成（事業別売上高の内訳） | 印字値（JCE-038 の事業別売上高） | 既存 |
| | 関連する経済指標の現在値と推移 | 公的統計のスナップショット（§4） | **新規** |

観点4で有利子負債や手元流動性は扱わない。現在の財務レコード（売上高・利益・純利益・総資産・純資産・従業員数）に無い項目を、無いまま分析に使わない。データ拡張が必要なら別途の判断にする。

## 4. 経済指標スナップショット（新規の仕組み）

観点5の土台。経済指標データブック（OneDrive の Excel）はサイトから直接読めないため、サイト用のスナップショットを repo 内のコンテンツとして持つ。

- **保存形式**: `src/data/indicators/<indicator-id>.json`。スキーマは `{ id, name, source: { name, url }, unit, frequency, observations: [{ date, value }], updatedAt }` とし、zod スキーマと data-integrity テストで検証する（他のコンテンツと同じ規律）。
- **対象指標（開始時 約15）**: 実質GDP、鉱工業生産指数、企業物価指数、消費者物価指数、完全失業率、有効求人倍率、現金給与総額（実質賃金）、輸出額（通関）、経常収支、日銀短観の業況判断DI、米実質GDP、米CPI、米非農業部門雇用者数、FFレート、ドル円相場。いずれもデータブックに登録済みの系列から選び、出典は公的一次情報（または FRED 等の公的集計）に限る。ファンドや証券会社の見通し文書は素材にしない（ライセンスと出典規律の両面から）。
- **業界との接続**: `src/data/industry-indicators.json` に業界→指標の対応と、接続を説明する一文を持つ。一文は「構造の説明」に限る（例:「海外売上高比率が高い業界のため、輸出額と為替を並べて表示する」）。因果の主張（「この指標が上がればこの業界の業績が上がる」）は書かない。対応表は編集物として revisions の仕組みで版管理する。
- **更新**: 月次。月次の X 分析投稿と同じ公的統計の取得に合わせてスナップショットを生成し、コンテンツとしてコミットする。サイトは実行時に外部へ取りに行かない（静的サイトの性質を保つ）。
- **表示**: 指標ごとに最新値・前回値・1年の推移（小さなグラフ）を出す。「環境の提示」であって予測ではないことを、観点5の冒頭に明記する。

## 5. 表示仕様

- レポートページに「分析」部を追加し、5観点の章立てで見せる。各観点は「自社の値 → 業界分布（中央値・四分位・順位・パーセンタイル）→ 計算式と出典」の順で統一する。
- 印刷レイアウトは既存のレポート印刷 CSS を踏襲する（JCE-073 の印刷対応と同じ流儀）。
- 有料層の境界は表示単位で決める: 無料は観点ごとの要点（自社の値＋業界中央値）まで、有料は分布の全体・推移・指標連携・比較・PDF。
- 新規ルートは /analysis と /indicators/[indicator-id]（指標数分のみ）のみ。会社数に比例するルートは増やさない。

## 6. 課金仕様

- **ゲート**: plan.ts に分析層の判定を新設する。JCE-075 の PREMIUM_FEATURES_OPEN とは独立にし、075 で開いた範囲は開いたままにする（フラグを戻す形の再有料化はしない）。
- **販売経路**: 既存プラン（診断サイト側の Stripe Checkout、親ドメイン Cookie 共有）の上位層として販売する。前提タスクとして、Stripe の実績（加入者数・継続率）の確認と、既存加入者の扱い（分析層を含むか、追加料金か）を決める。
- **B2B単品**: 分析レポート PDF の単品販売（受容帯 15,000〜30,000円/件）は Phase 3 の判断ポイントとする。与信判断そのものは売らない（§7）。

## 7. 線引き（不変条件の確認）

- **総合スコア・格付け・偏差値のような単一の数への圧縮はしない。** 「優位性」は観点ごとの分布上の位置で示す。5観点を合成した点数は作らない。
- **投資助言に当たる表現は出さない。** 買い・売りの推奨、目標株価、将来の業績の予測は書かない。会社予想を示す場合は「会社予想（短信）」のバッジで自社の計算・分析と分離する（JCE-073 の規則）。
- **株価・時価総額・PER/PBR は扱わない**（不変条件4）。ROE/ROA も既存の計算レイヤーに無く、広げない。
- **与信判断（倒産確率・信用評点）は作らない。** BtoB 調査で需要が確認できても、百科事典の出典規律では裏付けが取れない領域には入らない。
- 経済指標との接続は「構造と環境の提示」であり、業績との因果を主張しない。

## 8. 品質ゲート

- 新規の計算指標は、Python による独立再計算と一致を確認してから載せる（特集記事 JCE-074 と同じ手順）。
- vitest: 指標 JSON のスキーマ検証、対応表の参照整合性（業界ID・指標ID の実在）、分布規則（MIN_DISTRIBUTION、PEER_WINDOW_DAYS）のテストを data-integrity に追加する。
- 描画確認: 開発サーバーで分析レポート（対象会社数社）と /analysis、指標ページを実描画して確認する。
- コミットゲートは従来どおり終了コード判定（tsc / eslint / vitest）。

## 9. 実装フェーズ

- **Phase 1 — 5観点フォーマット**: 既存10指標を5観点に再編し、観点1（順位・パーセンタイル）と純資産推移を足して、レポートの分析部として実装する。既存データのみで完結する。
- **Phase 2 — 外部環境**: 指標スナップショットのスキーマと初期15指標、業界対応表、観点5の表示。月次更新の生成手順を月次 X 分析の作業に組み込む。
- **Phase 3 — 課金**: 分析層のゲートとプラン連携、PDF 出力、B2B 単品販売の判断と実装。

## 10. 判断ポイント（推奨つき）

1. **課金の形**: 既存プランの上位層として出す（推奨。販売・認証の仕組みが既にある）か、分析データ単独の別プランにするか。
2. **指標の更新頻度**: 月次（推奨。X 月次分析と同じ取得に相乗りでき、鮮度と運用コストの釣り合いがよい）か、四半期か。
3. **B2B単品の開始時期**: Phase 3 で、B2C の分析層の反応を見てから判断する（推奨）。

## 11. やらないこと

- 総合スコア・格付けの創作、投資助言、株価系指標の追加。
- ファンド・証券会社の見通し文書の転載・要約の販売。
- 会社数に比例する新規ルートの追加（デプロイのファイル数上限のため）。
- JCE-075 で無料化した範囲の再有料化。
