# 情報の訂正ワークフロー

公開中の内容は、リポジトリ内のデータファイル（`src/data/`）から作られています。
**リポジトリが唯一の正本**で、管理画面はそれを編集・確認するための道具、Gitが履歴、デプロイが公開です。

```text
読者の報告 → 管理画面の報告一覧 → 出典で確認 → ローカルで訂正（改訂記録を作成）
→ 差分を確認 → コミット → プッシュ → デプロイ → 報告を「解決済み」に
```

報告と改訂は別のものです。

- **報告**：読者が「ここが違う」と伝えたもの。サーバー（データベース）に保存されます。
- **改訂**：実際に内容を変えた記録。`src/data/revisions/` に1件1ファイルで保存され、Gitで管理されます。

---

## 1. 報告を確認する（本番の管理画面でもローカルでも可）

1. `/admin/reports` を開く（ログインが必要です）
2. 報告の「詳細・出典の確認・メモ」を開く
3. 「出典で確認する」の原文リンクから、有価証券報告書などの該当箇所を確認する
   - 数値や記述ごとの根拠ページは `docs/research/<企業ID>.md` に記録されています
4. 状態を「調査中」にし、確認した内容を「訂正メモ」に書く
   - 誤りでなかった場合は「対応不要」にし、理由をメモに残して終わりです

## 2. ローカルで訂正する

**本番の管理画面からは編集できません。** 必ず手元の環境で行います。

```bash
git pull                 # 最新の内容から始める
npm run dev              # http://localhost:3000/admin
```

1. `/admin/companies/<企業ID>` の「編集する（ローカル）」を開く（用語は `/admin/terms`）
2. 該当の項目を直す
   - 金額は有価証券報告書と同じ **百万円** で入力します（保存時に円に換算）
   - 確認できない数値は空欄にし、「基本情報」の状態を「要確認」にして理由を書きます
   - 各項目の「出典」から原文を開いて確認できます
3. **「変更内容を確認」** を押し、変更前・変更後を確かめる
4. **変更の要約**（1行）と **理由と根拠**（確認した出典とページ、きっかけの報告）を書く
5. **「データファイルに保存（改訂記録を作成）」** を押す

保存されるのは次の2つです。まだ公開はされません。

- `src/data/companies/<企業ID>.json`（内容）
- `src/data/revisions/<日付>-company-<企業ID>-<ランダム>.json`（改訂記録：変更前・変更後・理由・日時）

### 保存が止められる場合

エディタは、次の場合に保存を拒否します。

| 状況 | 理由 |
|---|---|
| 編集を始めた後にファイルが変わった（`git pull` など） | 他の変更を黙って上書きしないため。再読み込みしてやり直します |
| 出典のない項目がある／出典一覧にない出典を参照している | 出典のない事実は載せないため |
| 出典を削除する | 確認のチェックと理由が必要です。まだどこかの項目が参照している出典は削除できません |
| 一文の説明が90文字を超える、投資指標にあたる語が入っている など | 掲載ルール（`tests/data-integrity.test.ts` と同じ） |
| 要約・理由が空、または何も変わっていない | 改訂記録が「なぜ・何を」を答えられなくなるため |

## 3. 差分を確認してコミット・プッシュする

エディタは Git を一切操作しません。次はすべて手で行います。

```bash
npm run content:check    # 掲載ルールのテスト＋型チェック＋lint
npm run content:diff     # 変更ファイル・新しい改訂記録・差分を表示（読み取りのみ）

git add src/data
git commit -m "content: <改訂ID> <変更の要約>"
git push
```

デプロイが終わると公開ページに反映されます。

## 4. 報告を閉じる

公開を確認したら、報告の詳細で状態を「解決済み」にし、訂正メモに改訂IDとコミットを書き足します。

---

## あとから辿るには

| 知りたいこと | 見る場所 |
|---|---|
| 何が変わったか | `/admin/revisions/<改訂ID>` の変更前・変更後、または `git log -p -- src/data` |
| なぜ変わったか | 改訂記録の「理由・根拠」、報告の「訂正メモ」 |
| どの出典が根拠か | 改訂記録の理由、企業の出典一覧、`docs/research/<企業ID>.md` |
| いつ変わったか | 改訂記録の日時、コミット日時、デプロイ履歴 |
