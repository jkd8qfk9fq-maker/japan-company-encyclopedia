# 登録 autopilot の運営者の判断事項（2026-10-18）

> **2026-10-18 に運営者が「全て許可」。判断1（EDINET のみ）・判断2（上場でない相手は結ばない）は推奨案どおり実装済み（JCE-023）。判断3（既存258社）は未実施のまま（一括変更のため、差分を先に出す手順が要る）。** 以下は決定前の整理として残す。

3つは**互いに独立**している。どれかを決めても他は決まらない。推奨案は理由つきで付けたが、**決まったものはない**。決めたら `docs/decisions.md` に記録する。
数値は 2026-10-18 時点の実測（再現: 下の各項の「確かめ方」）。

---

## 判断1. 企業の公式サイトを出典に使ってよいか

**事実**
- 出典は原則 EDINET。EDINET 以外（会社の公式ページ・IR 資料）を使うと、`finalize` が「一次資料かどうかは人が確認すること」と注意を出し、確認シートに目立つ形で出る。
- 今回の10社のうち3社が、公式サイトの資料を出典に持つ（関係性の裏付けに使われている）:

| 企業 | EDINET 以外の出典 | ホスト |
|---|---|---|
| 双日 | 4件（ロイヤルHDとの資本業務提携の発表、さくらインターネットの適時開示2件・双日との発表） | www.sojitz.com、www.sakura.ad.jp |
| スズケン | 2件（Welby の発表） | welby.jp |
| 大林組 | 2件（三菱地所の発表、三菱地所との共同プレスリリース） | www.mec.co.jp、www.obayashi.co.jp |

- 各社サイトの**利用条件は未確認**（`docs/source-terms.md` 3節。公開済み企業の出典でも16ドメインが未確認のまま）。現在の使い方は「リンクを出典として示し、事実を自分の言葉で書く」で、本文や画像の転載はしていない。
- 自動では収集しない（autopilot の既定）。エージェントが web を使うのは `run --allow-web` のときだけ。

**選択肢**
| 案 | 内容 | 影響 |
|---|---|---|
| A. 当面は EDINET のみ（推奨） | ゲートで EDINET 以外の出典を拒否する。関係を公式資料で補う案件は、あなたが個別に許可 | 上の3社は、該当の関連企業（さくらインターネット、Welby、三菱地所）を外す／出典を EDINET に差し替える必要がある。関連企業が減る |
| B. 条件を確認した会社だけ許可 | 許可ドメインの一覧をリポジトリに持ち、一覧にあるものだけ通す | 一覧の維持が要る。確認は運営者（各社の利用規約） |
| C. 今のまま（人が確認シートで判断） | 変更なし | 利用条件が未確認のまま公開しうる。確認シートの「EDINET 以外」を毎回読む必要 |

**推奨の理由**: 不変条件3は「会社の公式ページ」を一次資料に含めるが、利用条件が未確認のものを機械で通す根拠はまだない。A なら、判断が済むまで自動で増えない。
**実装の大きさ**: A は `finalize.mjs` のゲートに数行（許可ドメインの一覧を空にしておく）。B は一覧ファイル＋同じゲート。
**確かめ方**: `node scripts/pipeline/autopilot.mjs review <id>` の「2. 一次資料の出典」の「種別」列。

## 判断2. 上場廃止（とみられる）会社へのリンクの扱い

**事実**
- 関連企業のリンク先が、EDINET コードリストに載っていない（上場廃止の可能性）ことが、10社のうち2社で起きている。確認シートに「確認」として出る:

| 企業 | リンク先 | 有報の関係 |
|---|---|---|
| 出光興産 | 富士石油（5017、掲載済み・数値のみ） | 連結子会社（議決権92.49%） |
| 大和ハウス工業 | 住友電設（1949、掲載済み・数値のみ） | 連結子会社（議決権100%）。エージェントの調査では、東証の適時開示で上場廃止日は2026年3月3日（未検証） |

- ほかに、豊田通商の大株主・豊田自動織機（6201）が、同じ理由で `taxonomyGaps` に付記されている（リンクは結んでいない）。
- `docs/pipeline.md`「上場廃止会社の扱い」は**仕様判断待ち**のまま（コードも未変更）。数値のみのエントリー（公開されない）へのリンクは、読者には**文字だけ**になる（公開ラインの実装）。つまり読者に壊れたリンクは出ない。

**選択肢**
| 案 | 内容 | 影響 |
|---|---|---|
| A. 有報の関係をそのまま結ぶ（今のまま、確認シートで確認） | 子会社であることは事実として正しい | 相手のページが公開されない間は文字のみ。将来相手が公開されたとき「上場廃止」の表示が要る（スキーマ・表示の変更） |
| B. 結ばない（推奨） | コードリストで「上場」でない相手は結ばず、`warnings` に有報の記載を残す | 子会社という重要な関係が、サイト上は消える（文章の中の記述は残せる）。後で結び直せる |
| C. 「過去の上場会社」を表す仕組みを作る | 会社マスターに上場／上場廃止の区別を持たせる | スキーマと表示の変更。このサイトの前提（上場企業の百科事典）に触れる |

**推奨の理由**: 上場状況は推測で確定しない（不変条件1）。B なら、コードリストが唯一の根拠として一貫する。C は大きい決定なので、必要になってから。
**実装の大きさ**: B は `prose-policy.mjs` の `not-in-ledger` を `review` から `error` にする（1行とテスト）。
**確かめ方**: 確認シートの「5. … 機械の検査が人の確認を求めたもの」、または `node scripts/pipeline/check-policy.mjs <id>`。

## 判断3. 登録済みの解説つき258社の文章を、新しい規則にどう合わせるか

**事実**（実測。`checkProsePolicy` を登録済みの全解説つきエントリーに当てた結果。企業数）
| 規則 | 公開済み184社のうち | 要確認74社のうち |
|---|---|---|
| 一文の説明は句点1つ | 183 | 73 |
| 一文の説明は100文字以内 | 180 | 74 |
| 売上高・当期純利益以外の利益などの財務語を書かない | 180 | 74 |
| 有報を主語にしない（事業・沿革・ビジネスモデルの文） | 144 | 69 |
| 財務語の金額（受注高・総資産など）を書かない | 135 | 62 |

- **公開済み184社のすべてが、いずれかの規則に当たる。** 規則は2026-10-17より前に書かれた内容に遡って適用していない。
- CLAUDE.md の不変条件4（「売上高と純利益だけが財務」）に照らすと、公開中のページにセグメント利益・営業利益などの記述が残っている。これは autopilot の問題ではなく、既存の公開内容の問題。
- `data-integrity` テストはこの規則を見ていない（見ると既存データが全件落ちる）。規則は新しい登録（`finalize`）だけに適用。

**選択肢**
| 案 | 内容 | 費用・手間 |
|---|---|---|
| A. 新規のみ（今のまま） | 既存は触らない | なし。公開中の内容は不変条件4と食い違ったまま |
| B. 優先度をつけて書き直す（推奨） | 公開済みのうち不変条件4に当たるもの（財務語）から。不備の行だけをモデルに直させる専用の経路を作る（`redo` は全体の書き直し） | 概算: 1社あたり 0.5〜1.5 ドル×258 社 = 約 130〜390 ドル。確認シートの読みも社数分。新しい登録系のコード（昇格ではなく修正。Revision を書く）が要る |
| C. 全面の書き直し | 258社を autopilot の `redo` で group1・group2 とも | 約 2.3 ドル×258 = 約 590 ドル、実行時間は約 34 時間。確認も全社 |
| D. 公開を絞る | 該当が重いものを一時的に非公開（要確認に戻す） | 公開企業が減る。JCE-018 の公開ラインの運用判断 |

**推奨の理由**: 不変条件4は P0 扱い。まず「財務語」だけ（`forbidden-financial-term`／`-amount`）を直せば不変条件への抵触は解消し、文体の規則（一文・有報を主語）は後回しにできる。ただし**新しい経路（既存エントリーの修正）は未実装**で、実装すれば別の確認が要る。
**確かめ方**: `node scripts/pipeline/audit-policy.mjs`（読み取り専用。`--list <規則>` で該当企業の一覧）。
