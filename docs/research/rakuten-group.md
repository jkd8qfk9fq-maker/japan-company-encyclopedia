### draft-entry.json のラベル2件を修正した（数値はすべて正しかった）

**1. `netIncomeLabel`** — draft は `当期利益又は当期損失（△）：親会社の所有者に帰属（IFRS）`。
これは XBRL 要素 `jpcrp_cor:ProfitLossAttributableToOwnersOfParentIFRSSummaryOfBusinessResults` の
**taxonomy ラベル**で、有報の五年表にこの文字列は印字されていない。
印字は **`親会社の所有者に帰属する当期損失（△）`**（5年とも損失なので「当期損失」と刷られている）。
protocol は「ラベルは filer の印字どおり」なので、印字のほうへ直した。
`indicators.txt` を NFKC 正規化して部分一致を確認済み（draft のラベルは MISS、印字ラベルは OK）。

**2. `profitLabel`** — draft は `税引前利益`。これも要素のラベルで、印字は
**`税引前当期利益又は損失（△）`**。同じく印字のほうへ直した。draft の `税引前利益` は
`indicators.txt` に部分一致しない（MISS）ことを確認済み。

いずれも**数値の誤りではなくラベルの取り違え**。`revenueLabel`（売上収益）、`totalAssetsLabel`（総資産額）、
`netAssetsLabel`（親会社の所有者に帰属する持分）、`employees` は draft のままで印字と一致していた。

### そのほかラベル・値の確認

- **`netIncome` の取り違え確認**: 同じ表に「親会社の所有者に帰属する当期包括利益」
  （2025年12月期 △3,997百万円）が並んでいる。採用したのは当期損失 △177,886百万円のほうで、
  包括利益ではない。`summary.json` の `figures.netIncome` に出る要素は
  `ProfitLossAttributableToOwnersOfParentIFRSSummaryOfBusinessResults` の1件だけで、
  候補が複数あって選んだわけではない。
- **`netAssets` は総額ではなく親会社持分**。この有報の五年表には「資本合計」「純資産額」の行がなく、
  印字されているのは「親会社の所有者に帰属する持分」だけである（`figures.netAssets` の要素も
  `EquityAttributableToOwnersOfParentIFRSSummaryOfBusinessResults` の1件のみ）。
  protocol の「filer が総額をタグ付けしていない場合は親会社持分にフォールバックし、ラベルでそれを示す」
  に従い、`netAssetsLabel` に「親会社の所有者に帰属する持分」と明記した。非支配持分は含まれていない。
- **`employees`**: 五年表の「従業員数(名)」。注記4に「従業員数には、使用人兼務取締役、派遣社員及び
  アルバイトは含んでいません」とあり、その旨を businessModel の company ステップに書いた。
- **会計基準**: `cover-page.txt`「会計基準、DEI」= IFRS。五年表の注記1も「国際会計基準（以下「IFRS
  会計基準」）により連結財務諸表を作成しています」。5年とも `ifrs`。
- **修正再表示**: brief の 修正再表示チェックは「前期有報と重複年度は全て一致（修正再表示なし・8行）」。
  verify-financials は24行一致。「突き合わせられる行がない」項目はない。前期有報との間に修正再表示はない。
- **株価収益率が「－」**: 五年表の注記3に「株価収益率については、当期損失が計上されているため
  記載していません」とある。当エントリーは投資指標を一切保持していないので影響しない。
- **短信クロスチェック**: 実施していない。有報のタグ値と印字が6項目×5年で一致しており、齟齬がないため。

### revenueBasis / netIncomeBasis — 設定していない

**判断: 連結範囲（perimeter）の変更はなく、あるのは会計基準の適用＝測定方法の変更なので、
basis は付けず `note` にした。**

根拠は五年表の注記5:
「IFRS第17号「保険契約」を第27期の期首から適用し、基準移行日である2022年１月１日時点に基準変更による
累積的影響額を反映しています。これに伴い、第26期に係る主要な経営指標等については、当該会計基準を
遡って適用した後の指標等となっています。」

- 遡及適用されたのは **第26期（2022年12月期）だけ**。第25期（2021年12月期）は適用前の数値。
- 連結される会社の範囲は変わっていない（保険契約の測定・表示の基準が変わっただけ）。
- 会社が挙げる大きな事業の出入りも5年のなかにない。沿革にある 2023年4月の楽天銀行の上場や
  2024年11月・2022年10月の資本業務提携は、いずれも連結子会社のままで、非連結化ではない。

したがって basis は省き、**比較可能性が切れる境目を `note` で示した**:
2021年12月期に「この年度だけは IFRS第17号適用前」、2022年12月期に「この年度は遡及適用後」と書いた。
指示された切り分け（perimeter change → basis 両方を全年度／measurement-method change → note）の
後者にあたると判断した。

加えて **2024年12月期に `note` を1つ足した**。5年で唯一 `profit`（税引前当期利益又は損失）が黒字
16,277百万円になっている年で、MD&A (2)①（その他の収益）とセグメント情報の非経常的な項目の注記が
「AST SpaceMobile, Inc.株式の会計上の取扱いの変更による再測定益106,906百万円」を理由として挙げている。
これがないと、読者は本業が黒字化した年と読んでしまう。会社の説明の範囲だけを書き、評価は加えていない。

## 沿革の形式チェック

`history.txt` は「**その年の最初の事項には年月がインラインで付き、同じ年の2件目以降は月だけが印字される**」
形式だった。例:

```
2000年４月日本証券業協会に店頭登録      ５月本社を東京都目黒区中目黒２丁目６番20号に移転2001年３月『楽天トラベル』のサービスを開始
```

年セルが事項と完全に分離して出力される形式ではなく、月だけの行の年は直前の年ブロックから一意に決まる。
**したがって沿革は単独で健全**と判断し、フィリング内の第二のソースによる突き合わせは行っていない。

ただし**1か所だけ、1つの月セルに2つの事項が連結して出力されている箇所があった**:

```
10月北米最大級の会員制オンライン・キャッシュバック・サイトを展開するEbates Inc.を子会社化 携帯電話サービスに本格参入、『楽天モバイル』を提供開始
```

「携帯電話サービスに本格参入、『楽天モバイル』を提供開始」が 2014年10月なのか、日付セルが落ちた
別の行なのかが、このテキストだけでは確定できない。**この行を年付きの turning point としては使わず**、
年がインラインで印字されている「2019年10月『楽天モバイル』が携帯キャリアサービスを開始」を
モバイルの沿革項目に採った。2014年の本格参入は、その2019年の項目の `description` の中で
月を断定しない書き方（「2014年10月に携帯電話サービスへ本格参入したのに続くもので」）で触れている
— 10月であることは Ebates の行と同じセルにあるので月までは読めるが、`year` として独立した
項目にはしていない。

## Gaps and judgement calls

1. **draft のラベル2件を修正した**（`netIncomeLabel`、`profitLabel`）。いずれも taxonomy ラベルが
   入っていて、有報の五年表の印字と違っていた。上記「draft-entry.json のラベル2件を修正した」に詳細。
2. **`revenueBasis` / `netIncomeBasis` を設定しなかった**（上記）。IFRS第17号の適用は測定方法の変更で
   連結範囲の変更ではないため、`note` で処理した。
3. **`netAssets` が非支配持分を含む総額ではない**（上記）。有報の五年表に総額の行がないため、
   protocol のフォールバックに従って親会社持分を使い、ラベルで明示した。この点は他社エントリー
   （資本合計・純資産額を使っているもの）と横に並べるときの注意点になる。
4. **セグメント売上収益が内部取引消去前で、サービス別売上収益が連結後**という2種類の数値が
   同じ有報に載っている。entry では必ずどちらかを名前付きで書いた（「セグメントに係る売上収益」／
   「外部顧客に対する売上収益」）。両者を足したり比べたりはしていない。
5. **セグメント損益が Non-GAAP 営業利益ベース**で、IFRS 営業利益とは別物である。会社の社内指標を
   そのまま「利益」と書くと誤読されるので、businessModel の profit ステップで Non-GAAP と IFRS を
   並べて示した。
6. **モバイルエコシステム貢献は会社独自の社内調整**で、外部の会計基準に基づく数値ではない。
   金額は使ったが、「会社が金額に換算してセグメント損益に反映している」という出所つきの書き方に限った。
   算式の詳細（アップリフト効果・送客効果の計算方法、対象18事業）は entry には入れていない。
7. **`industries` を it（primary）／finance／telecommunications にした**。有報は業種を宣言していないので
   これは百科事典側の分類判断で、3つの報告セグメントにそのまま対応させた。`retail` は付けていない
   — 『楽天市場』は出店店舗が売る場の運営であり、会社が商品を仕入れて売る小売ではないため。
   楽天24やネットスーパーなど自社販売の要素はあるが、セグメントの主軸ではない。
8. **ZOZO・ソフトバンクとの違いは、両社を名指しせずに楽天自身の事実で書いた**。他社の有報は
   この evidence pack にないので、他社について何かを主張する根拠がない。代わりに
   (a) 『楽天市場』が自社仕入れではなく出店店舗の売る場であること、(b) フィンテックの売上収益が
   商品代金ではなく手数料・金利収益・保険料収入であること、(c) モバイルが自社ネットワークを持つ
   一方で3セグメント中いちばん小さく損失であること — この3点を description と businessModel、
   各セグメントの description に明示した。読者が並べたときに違いが出るのはこの3点である。
9. **流通総額（GMV）の金額は書いていない**。MD&A は「流通総額及び売上収益が成長し」と述べるだけで
   金額を開示していないため、数字を出せない。
10. **前年度比の％は会社が印字しているものだけを使った**（売上収益9.5％増など）。自分で計算した比率は
    entry に入れていない。
11. **2025年12月期の非経常的な項目（ネットスーパー事業の減損27,909百万円、楽天シンフォニーのOpen RAN
    事業の減損20,497百万円など）は entry に書いていない**。セグメント情報の注に列挙はあるが、
    当期損失の主因として会社が単一の説明をしているわけではなく、1文の `note` に収まらない。
    リサーチログにこう記録して、entry では触れないほうを選んだ。
12. **短信・統合報告書・会社サイトを参照していない**。有報だけで裏づけられたため。
13. **`relatedCompanies` は `[]`**（protocol どおり、別パスで調査）。みずほ証券・みずほフィナンシャル
    グループとの資本業務提携は沿革に書いたが、関係の登録は別パスの仕事。
14. `status` は `published`。null のままにした数値はない。
