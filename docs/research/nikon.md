### profit / profitLabel を全年度 null にした理由（最重要）

**有価証券報告書の「主要な経営指標等の推移」には `税引前利益又は損失（△）` の行が確かに印字されている**
（`indicators.txt`: 「税引前利益又は損失（△）（百万円）57,09657,05842,6694,533△106,511」）。
**しかし、EDINETが配信するこの有報のXBRLには、この行に対応するタグ付きデータが存在しない。**
evidence pack の `brief.md` も「profit が5年表に見当たらない」と報告しており、`draft-entry.json` の
`profit` は五年とも `null` で生成されている。

印字テキストから5つの数値を目で切り出して入れることは技術的には可能だが、上の印字は区切り文字の
ない連結文字列であり、桁の切り出しを人手で行った時点で「フィリングのタグ付き値をそのまま写す」と
いう保証が崩れる。No fabrication の原則から、**タグがない値は転記せず null のままとし、
`status` を `needs-attention` にしてその旨を明記した**。

代替値は入れていない。特に:
- **当期包括利益（70,646 / 60,094 / 91,724 / 1,264 / △34,799）は使っていない** — 包括利益であり、
  プロトコルが明示的に禁じている行。
- **当期利益（非支配持分を含む）は使っていない** — 五年表にその行の印字がなく、また
  `netIncome` と混同される。
- **営業利益も使っていない** — プロトコルが `profit` は営業利益ではないと定めており、
  かつ五年表に営業利益の行がない（MD&Aには2026年3月期の営業損失1,124億48百万円があるが、
  五年分はそろわない）。

なお、税引前損失△106,511百万円という2026年3月期の値そのものは、MD&A「税引前損失は1,065億11百万円」
と一致しており、数値が誤っているという話ではない。**タグ付きデータとして取得できないだけである。**

  売上収益は同じ基準の連結売上収益として並べてよいと判断した。

## Gaps and judgement calls

1. **`profit` 全年度 null（`status: needs-attention`）。** 理由は上記のとおり。エントリの
   `status.notes` にも同じ趣旨を記載した。ページには `profitLabel` も出ないことになる。
2. **`revenueBasis` / `netIncomeBasis` は両方とも省略。** 理由は Financials の項に記載。
3. **「その他」セグメント（売上収益3,664百万円）は `businesses` に含めていない。** 有報が
   その中身を説明していないため。ただし従業員数の表では「その他」4,406人と最大級の人数になっており、
   何らかの実体があることは読み取れる。説明がないので書かなかった。
4. **コンポーネント事業の子businessの名称。** 注記6の表記を採用（MD&Aの「インダストリアル
   ソリューションズ事業」とは表記が異なる）。理由は Segment ordering の項に記載。
5. **短信・統合報告書との突き合わせは行っていない。**
6. **業種（industries）** は `electronics` を primary、`semiconductors` を従とした。
   後者は精機事業が半導体露光装置をつくること（注記6）による判断で、有報の分類ではない。
7. **上場取引所は東京証券取引所プライム市場のみ。** 表紙の記載がそれだけで、外国市場への上場の
   記載はない。
