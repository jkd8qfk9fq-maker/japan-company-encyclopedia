IFRS を採った理由は3つです。(1) 注1「第18期より国際会計基準（以下「IFRS」という。）に基づいて連結財務諸表を作成しております」＋DEI「会計基準＝IFRS」で、連結財務諸表そのものが IFRS で作られている。(2) 表A が5年分をカバーする主表で、表B は移行期の3年だけの参考表。(3) **注6「第18期の日本基準による諸数値につきましては、金融商品取引法第193条の２第１項の規定に基づく監査を受けておりません。」** — 2023年12月期の日本基準の数値は無監査です。監査済み・主表・現行基準がそろう IFRS を採るのが妥当と判断しました。結果として2022〜2025年の4年が一貫した IFRS の系列になります。

**2021年12月期は表B しかありません**（表A の移行日列に売上・利益がない）。したがってこの年だけ日本基準です。総資産・純資産もこの年は表B の値（総資産額 5,158,196／純資産額 3,346,409）で統一しました。表A の移行日列（2022年1月1日）にも総資産額 5,285,056 と親会社の所有者に帰属する持分 3,033,680 があり、pack はこれを 2021-12-31 に紐づけてタグしていますが、**日本基準の年の行に IFRS 移行日の貸借対照表を混ぜないため採っていません**。`verify-financials.mjs` はどちらでも通る（両方がその決算期の候補として立っている）ので、これは検査では捕まらない種類の判断です。

`netAssets` について: 表A（IFRS）は**資本合計の行を印字していません**。印字されているのは「親会社の所有者に帰属する持分」だけなので、protocol の fallback（「`netAssets` は 純資産額 / 資本合計 を優先し、filer が総額をタグしない場合にのみ 親会社の所有者に帰属する持分 に落とす」）に従い、2022〜2025年はその値を入れ、`netAssetsLabel` がそれを明示しています。参考として資本合計は2025年12月期で5兆229億円（非支配持分2,757億円を含む）で、これは2025年の `note` に書きました。

`netIncome` は包括利益ではありません。表A は「親会社の所有者に帰属する当期包括利益」（975,145／591,848／842,911／129,448）を次行に、表B は「包括利益」（495,449／880,770／575,268）を次行に印字していますが、**いずれも使っていません**。

### `revenueBasis` / `netIncomeBasis`: NOT set — decision and reason

**設定しませんでした。** 5年のあいだに起きているのは**会計基準の変更（日本基準 → IFRS）**で、これは測定方法の変更であり、連結範囲（perimeter）の変更ではありません。非継続事業の区分、子会社の連結除外、取得の遡及適用のいずれも有報にありません。2022年の重複年で比べると売上は 2,324,660 → 2,316,086（差0.37％）で、収益の範囲がほぼ同じであることが実際の数字からも確認できます。

その代わり、(1) 各年の `accountingStandard` が `jgaap` / `ifrs` を持ち、(2) 各年の `revenueLabel`／`profitLabel`／`netIncomeLabel`／`netAssetsLabel` が表の行名の違いをそのまま示し、(3) 2021年と2022年に `note` を置いて、どの表から採ったか・重複年の日本基準の値・IAS第12号の遡及適用・収益認識会計基準の適用開始時期を書きました。2022年の history 項目でも同じことを説明しています。

**これは見直しの余地がある判断です。** 基準変更を「revenue が覆う範囲の変更」と読めば basis フィールドを10行すべてに置いてチャートを割る選択もありえます。私は protocol が perimeter（非継続事業・遡及適用）を明示的に列挙し、かつ年別 `accountingStandard` という別の仕組みを持っていることから、基準変更は `accountingStandard` ＋ `note` で扱う設計だと読みました。純利益の重複年の差（498,452 対 461,069、8.1％）は売上の差より大きいので、レビュアーが別の判断をするならその点が根拠になります。

そのほか有報が記録している測定方法の変更:
- 注4（表B）「「収益認識に関する会計基準」（企業会計基準第29号 2020年3月31日）等を第17期の期首から適用」→ 2021年12月期（第16期）は適用前。2021年の `note` に記載。
- 注5（表A）「一部の在外連結子会社及び在外持分法適用関連会社は、第18期より、IAS第12号「法人所得税」（2021年5月改訂）を適用。本改訂は遡及適用され、第17期は、遡及適用後の数値」→ 2022年の `note` に記載。

- 報告セグメントは**2つ**です:「報告セグメントを「国内O&G」及び「海外O&G」に区分し、「海外O&G」については、当社グループの主要オペレーター・プロジェクトである「イクシスプロジェクト」とそれ以外の海外プロジェクトから構成される「その他のプロジェクト」に区分しております」。したがって top level は 海外O&G・国内O&G・その他 の3つで、イクシスとその他のプロジェクトは海外O&G の `children` です。
- **children 内の「その他のプロジェクト」は最後に置いていません。** 名前に「その他」が付きますが、これは報告セグメントに含まれない残余バケツではなく、海外O&G という報告セグメントを構成する側の区分（「それ以外の海外プロジェクト」の集約）で、連結売上収益の74％を占めます。したがって revenue 順で先に置きました。最後に回す規則が効くのは、有報が「報告セグメントに含まれない事業セグメント」と注記している top-level の「その他」だけです。
- top-level の**「その他」は最後**です（注1「「その他」の区分は、報告セグメントに含まれない事業セグメントであり、再生可能エネルギー・電力関連事業及びCCS・水素事業等を含んでおります」）。外部収益17,176百万円は国内O&G より小さいので順位は変わりませんが、規則として記録します。

**セグメント利益の定義が普通と違います。** 有報は「報告セグメントの利益は連結損益計算書の**親会社の所有者に帰属する当期利益**で表示しております」としています。つまり営業利益ではなく税引後・非支配持分控除後です。エントリの記述はどこでもこの定義を明示しました。この定義のおかげで見える事実として、その他のプロジェクトは外部収益がイクシスの4.7倍あるのにセグメント利益はイクシスを下回ります（131,790 対 270,801）。同区分の法人所得税費用が△702,992百万円と巨額であるためで、これは表の数字だけから言える範囲で書き、産油国の税制によるものという以上の推測はしていません（連結の法人所得税費用7,438億円が税引前利益1兆1,734億円の6割を超える、という事実も同様）。

## 沿革 date format

`history.txt` は410字と短く、**日付がすべて各事象の直前にインラインで印字されています**（「2005年11月国際石油開発株式会社及び帝国石油株式会社は…」「2006年４月当社設立（資本金300億円）。東京証券取引所（市場第一部）に上場。」「2021年４月商号を株式会社INPEXに変更。」）。年セルが事象と分離しているブロックは**ありません**。したがって沿革はそれ単体で健全で、第二のソースは不要でした。ヤマトHD とは逆のケースです。
