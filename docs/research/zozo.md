### basis の判断 — revenueBasis / netIncomeBasis は設定しない

当期にLYST LTDが連結対象に加わっている（2025年4月18日付で全株式取得、2025年5月より連結）。
これは **取得日以降の期間だけを連結に取り込む通常の企業結合** で、過年度を遡って作り直す
（retroactive presentation）処理は行われていない。非継続事業としての表示もなく、
MS等の生産事業・Made by ZOZO の終了も特別損失として当期に計上されているだけで、
過年度の売上高から抜き出してはいない。

したがって **集計範囲（perimeter）の不連続は生じていない**と判断し、
`revenueBasis`／`netIncomeBasis` はどの年度にも置かなかった。代わりに2026年3月期の `note` で、
LYSTが当期から加わったこと、当期のLYSTの売上高57億7,600万円と商品取扱高422億4,500万円、
過年度はLYSTを含まず遡及して作り直されていないことを明記した。

`note` を置いたのは2年度だけ。

- 2022年3月期: 臨時雇用者の人員の表示方法の変更（第24期以前は労働時間を8時間換算、第25期より
  時間換算せず年間平均人員）。`従業員数` 本体の数え方は変わっていないが、外数が同じ数え方では
  ないため読者が誤解しないように書いた（`indicators.txt` 注記2）。
- 2026年3月期: LYSTの連結開始と、MS等の生産事業・Made by ZOZO の終了に伴う特別損失
  合計727百万円（減損損失329百万円＋事業整理損失397百万円）。

## Segment ordering — 単一セグメントなので「セグメントの内訳」ではない

有価証券報告書は「当社グループはEC事業の単一セグメントであるため、記載を省略しております」と
述べており、**セグメント別の売上高は開示されていない**。
そこで会社自身が MD&A で示す事業区分別の表（［表３］事業別前期比）を使った。会社はこの表を
「当社グループはEC事業の単一セグメントであるため、セグメント別の記載は省略しておりますが、
単一セグメント内の各事業区分の業績を以下のとおり示しております」と前置きして掲げている。
**これはセグメント情報ではない**（プロトコルの「単一セグメントの場合」の扱い）。

**順序についての判断**: 売上高で並べると「その他」が2番目になり、商品取扱高の順位
（ZOZOTOWN → LINEヤフーコマース → LYST → その他 → BtoB）とは入れ替わる。
`revenue` に採っているのが売上高なので、プロトコルどおり **売上高** で並べた。
入れ替わる理由は、受託販売が手数料だけを売上高に計上する一方、送料収入・決済手数料収入は
そのまま売上高になるためで、この事実（受託販売手数料としての計上）は事業の内容と
MD&A に明記がある。その他の description に、この順位の入れ替わりをそのまま書いた。

`children` を置いたのは ZOZOTOWN事業だけで、会社自身が「『買取・製造販売』『受託販売』
『USED販売』の３つの事業形態で構成されております」と述べているため。子の順序もこの3つを
売上高の大きい順（受託販売 → USED販売 → 買取・製造販売）にした。
「その他」を businesses に入れたのは、会社が送料収入・決済手数料収入等とその他商品取扱高の
内訳を具体的に説明しているため（プロトコルの条件を満たす）。

### 沿革の形式（日付の整合性の確認）

`history.txt` は `年月概要1998年５月輸入CD・レコードの通信販売を目的に㈲スタート・トゥデイを設立
2000年１月インターネット上のCD・レコードの輸入販売サイト「STMonline」の運営を開始…` という形で、
**最初から最後まで各出来事の直前に年月がインラインで印字されている**。年のセルが出来事と別に
出力されている箇所はなく、セルのずれは構造的に起こりえない。よって沿革だけで日付の対応が
確定し、別ソースの裏取りは不要と判断した（ニトリと同じ形式、良品計画の後半とは違う形式）。

なお2019年の資本業務提携（9月）とTOBによる連結子会社化（11月）は、`affiliates.txt` の
親会社の記載（Zホールディングス中間㈱が議決権比率51.9％を所有）と整合しており、結果として
裏づけもある。2025年4月のLYST取得は `md-and-a.txt` ③（2025年4月18日付で全株式取得、
2025年5月より連結）が日付を裏づけている。

## Gaps and judgement calls

1. **商号の表記**。`cover-page.txt` の「会社名、表紙」は半角の **株式会社ZOZO**、EDINET の
   filerName は全角の「株式会社ＺＯＺＯ」。プロトコルは 商号を有報の表紙から採ると定めているため
   `officialName` は半角の `株式会社ZOZO` にした（`draft-entry.json` も同じ）。
2. **セグメント別の売上高は開示されていない**（単一セグメント）。順位づけは会社が MD&A で示す
   事業区分別の表に基づき、それがセグメント情報ではないことを上に明記した。
3. **地域別の売上高が書けない**。本邦の外部顧客への売上高が90％を超えるため、有報は地域ごとの
   情報の記載を省略している。LYST（イギリス）が加わった当期についても内訳はない。
   LYSTの売上高57億7,600万円という事業区分の数値だけを書いた。
4. **「広告事業」に商品取扱高がない**のは有報の表に「－」と印字されているとおりで、
   売上高だけを記載した。
5. **年間購入者数などのKPIは「LINEヤフーコマース」「LYST」「BtoB事業」を含まない**（有報の注記）。
   entry では「ZOZOTOWNで買物をするユーザー」の数として書き、範囲を混同していない。
6. **㈱High Link は2026年3月期の数値に含まれない**（後発事象）。history と businessModel に
   事実として書き、財務数値には一切反映していない。のれんの金額や受け入れる資産・負債の額は
   「現時点では確定しておりません」と有報が述べているため書いていない。
7. **`industries` は retail（primary）と media**。media を足した根拠はファッションメディア
   「WEAR by ZOZO」の運営と、独立した事業区分としての広告事業（当期売上高118億8,400万円）。
   IT を足さなかったのは、会社が自らを EC事業の単一セグメントと位置づけており、システム開発は
   BtoB事業のなかの支援業務として書かれているため。
8. **ZOZO NEXT・ZOZO NEW ZEALAND の開発内容は会社名の役割欄どおりにしか書いていない**
   （「新規事業の創出、研究開発」「計測技術等の開発」）。有報はこれらの具体的な成果を
   当期の事業区分別の業績としては示していない。ZOZOSUIT と ZOZOMETRY については、
   有報が書いている範囲（米国での有料販売、2024年10月の提供開始）にとどめた。
9. **ブランド名・パートナー名は有報が名指ししたものだけ**（SALOMON、sanrio house、宝島社STORE、
   株式会社マッシュスタイルラボ、株式会社サンリオ、株式会社宝島社、LINEヤフー株式会社、Lyst、
   株式会社High Link とその「カラリア」）。それ以外のブランド・提携先は一切書いていない。
10. **`relatedCompanies` は `[]`**（プロトコルどおり、別パスで調査）。LINEヤフー株式会社は
    親会社かつ取引先という二重の関係にあり、別パスで扱う価値がある。
