### 子事業の区分と順序

事業の内容の原文：
「ファクトリー・オートメーション(FA)に欠かせない要素機器である自動制御機器(**方向制御機器、駆動機器、空気圧補助機器
などの空気圧機器のほか温調機器、センサー等**)を製造・販売する『自動制御機器事業』を営んでいます」。

- 子事業は上記4区分（方向制御機器／駆動機器／空気圧補助機器／温調機器・センサー等）とし、
  **順序は有報の列挙順そのまま**にした。**製品区分ごとの売上高は一切開示されていない**（製品及びサービスごとの情報は
  記載省略）ため、売上高で並べることはできない。売上高順を装わず、会社の列挙順を採ったことをここに明記する。
- 会社は前3区分をまとめて「空気圧機器」と呼ぶ。階層をもう一段作って `空気圧機器 > 3区分` とする案も検討したが、
  枝が2本になり図の情報量が落ちるため、**4区分をフラットに並べ、前3区分の `description` に
  「あわせて会社が『空気圧機器』と呼ぶ製品群を構成する」と明記する**形にした。区分そのものは会社の言葉のままである。
- **開発製品の区分への割り当てについて**：研究開発活動の「主な開発製品」表は22件のシリーズ名を列挙するだけで、
  どの製品区分に属するかは有報が書いていない。そのため、**区分名から直接読み取れるもの（電磁弁＝方向制御機器、
  シリンダ・アクチュエータ＝駆動機器、フィルタ・増圧弁など＝空気圧補助機器、サーモチラー・スイッチ・センサ＝温調機器
  ・センサー等）だけ**を各 child に置いた。区分が読み取れない製品は親の `products` に置くか、entry に入れていない。

## Gaps and judgement calls

1. **沿革の形式**：`history.txt` は「1959年４月焼結濾過体(フィルタ用焼結金属)の製造及び販売を目的に…」のように、
   **年月が各事象の直前にインラインで印字される形式**だった。年セルが分離して出力される形式ではないので、
   **沿革だけで日付が確定でき、フィリング内の第二のソースは不要**と判断した。
2. **1970年の history 項目**：沿革は駆動機器（エアシリンダ）を1970年6月、方向制御機器（直動形電磁弁）を1971年1月と
   別行で書いている。2つを1つの転換点としてまとめ、`year` は先に来る1970とし、`title` と `description` に
   両方の年月を明記した。
3. **製品区分別の売上高は非開示**：上記「Segment ordering」のとおり、子事業を売上高順にできなかった。
   会社の列挙順を採った。
4. **製品区分別の従業員数・利益も非開示**（単一セグメントのため記載省略）。entry でも区分別の数値は書いていない。
5. **開発製品の区分割り当て**：上記のとおり、区分名から直接読み取れるものだけを各 child に置いた。
   有報が区分を明示していない製品を推測で振り分けてはいない。
6. **`name` の全角/半角**：`name` `officialName` は有報の印字どおり全角の「ＳＭＣ」、`nameEn` `shortNameEn` は
   半角の SMC。検索や見出しで表記が割れる可能性があるため記録する。
7. **`industries`**：`INDUSTRY_IDS` に機械・FA に対応する id がないため、同じ工場自動化の領域にいるファナック・
   キーエンスと同じ `electronics` を primary 1件とした。空気圧機器メーカーであり、この分類は近似である点を記録する。
8. **短信のクロスチェックは未実施**：有報XBRLのタグ値と `indicators.txt` の印字が全項目一致し、齟齬がなかったため。
9. **`sources` の id は `yuho-2026`**：`draft-entry.json` の `sourceIds` に合わせた。2026年6月26日提出の
   第67期（2026年3月期）有価証券報告書を指す。
10. `indicators.txt` に印字されている株式関連の指標（株価収益率、1株当たりの各行、自己資本利益率など）は
    entry に一切転記していない。`md-and-a.txt` が触れる ROE も同様に書いていない。
