### 修正再表示チェック

`brief.md` の該当節は「前期有報が窓内に見つからず、比較していない」。これは**比較できなかった**という意味で、

### 訂正有価証券報告書（S100YVTZ）が何を訂正したか

パックの `corrections[].comparedToBase` は売上・純利益の5行について差異ゼロとしか言わないので、
キャッシュ済みの両方のXBRL_TO_CSVを要素ID×コンテキスト単位で全行突き合わせた
（`jpcrp030000-asr-001_E00394-000_2025-12-31_01_2026-07-27.csv` と `…_02_2026-08-12.csv`、各2,426行）。

- 差異は **5行のみ**で、すべて「これが訂正報告書である」ことを示すDEI・表紙の項目だった:
  - `jpdei_cor:NumberOfSubmissionDEI`（提出回数） 1 → 2
  - `jpcrp_cor:DocumentTitleCoverPage`（提出書類、表紙） 有価証券報告書 → 有価証券報告書（2026年８月12日付け訂正報告書の添付インラインXBRL）
  - `jpdei_cor:AmendmentFlagDEI`（訂正の有無） false → true
  - `jpdei_cor:IdentificationOfDocumentSubjectToAmendmentDEI`（訂正対象書類の書類管理番号） － → S100YSGA
  - `jpdei_cor:ReportAmendmentFlagDEI`（記載事項訂正のフラグ） false → true
- 残り2,421行（数値タグおよび194本のテキストブロック——沿革、事業の内容、関係会社の状況、役員の状況、
  役員の報酬等、株式の保有状況、連結財務諸表の各計算書と全注記を含む）は**完全に同一**。
  監査報告書のCSV（`jpaud-aai-cc-001` / `jpaud-aar-cn-001`）も両ファイルでバイト単位で同一。
- **結論**: 訂正が何を直したのかは、このエビデンスパックからは**特定できなかった**。タグ付けされた事実にも
  タグ付けされた本文にも変更がないので、訂正箇所はXBRLでタグ付けされていない部分（訂正報告書本体の
  「訂正の理由」「訂正箇所」の記述など）にあると考えられる。日立（役員の報酬等）や大成建設のように
  要素単位で特定することはできなかった。**推測は書いていない。**
  確実に言えるのは、本エントリーが載せる数値・セグメント情報・沿革・事業の内容は訂正の前後で1文字も
  変わっていない、ということだけである。

### 沿革の日付の形式について

`history.txt` は「年月／主要事項」が各行で**インラインに**並んでおり（例:「1949年９月朝日麦酒株式会社を発足し…」
「2011年７月純粋持株会社制に移行し…」）、年セルが事象から切り離されて出力される形式では**ない**。
したがって日付のずれは起こらず、沿革だけで日付は成立している。フィリング内の第二のソースによる
裏取りは不要と判断した。1889年と1949年の分割の経緯だけは表ではなく「設立の経緯」の本文に記載がある。

## Gaps and judgement calls

1. **`revenueBasis` / `netIncomeBasis` は設定していない（両方とも省略）。** 5年間を通じて
   非継続事業、事業の売却に伴う遡及的な組替え、取得の遡及適用のいずれも有報に記載がなく、
   売上収益が指す範囲は一貫している。当年度に起きたのは**報告セグメントの区分変更**であって、
   連結売上収益の集計範囲の変更ではない。したがってグラフを分断する必要はないと判断した。
2. **`note` は2025年12月期にのみ設定した。** 会計基準の変更・収益認識基準の変更・遡及適用・
   異例の期間長はいずれもない。設定した理由は、2025年12月期の減収・減益が有報自身の説明では
   サイバー攻撃によるシステム停止に強く起因しており、これを知らずに列を読むと年度間の比較を
   誤るため。有報の記述の範囲内に留め、影響額の推計などは一切書いていない。
3. **訂正有報が何を訂正したかは特定できなかった**（上記のとおり）。推測は書かず、
   訂正の前後で数値・本文のタグ付き内容が一切変わっていないという確認できた事実だけを記録した。
   本エントリーの内容は訂正の影響を受けない。
4. **修正再表示（過年度の再表示）の有無は未確認。** 前期有報がキャッシュの取得窓外で、
   パックが比較を行えていない。過年度数値は最新有報の値を採用している。
5. **決算短信によるクロスチェックは行っていない。** パックに含まれず、XBRLタグ値と印字が
   一致しているため追加取得の必要を認めなかった。
6. `netAssets` は「資本合計」ではなく「親会社の所有者に帰属する持分」。この会社が五年表に
   資本合計を印字していないためで、欠損ではない。ラベルがそのことを示している。
7. `shortNameEn` は `ASAHI GROUP`。英訳名 `Asahi Group Holdings, Ltd.` から法人格を示す
   `Holdings, Ltd.` を落としたもの。
8. `industries` は `food` を primary に設定。`INDUSTRY_IDS` に飲料・酒類にあたるIDがないため。
9. 業界内の位置づけ、競合、シェアなどの評価的な記述は一切書いていない（出典がないため）。
10. `relatedCompanies` は `[]`（別パスで調査する方針のため）。
