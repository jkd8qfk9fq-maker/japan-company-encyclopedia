### revenue の候補が2件 — どちらを採ったか

indicators.txt の連結経営指標等の表には**収益の行が2つ**並ぶ。

1. **収益合計** — 1,593,999 / 2,486,726 / 4,157,294 / 4,736,743 / 4,758,486（百万円）
2. **収益合計（金融費用控除後）** — 1,363,890 / 1,335,577 / 1,562,000 / 1,892,485 / 2,167,713（百万円）

**表の一番上に置かれている「収益合計」を採った。** 連結損益計算書でも、収益の各項目を積み上げた合計が

三菱UFJフィナンシャル・グループのエントリーが経常収益（差引前）を採っているのと同じ考え方。

5年すべての `note` に同年度の収益合計（金融費用控除後）を併記し、事業の並び順にもこちらを使った
（ビジネスモデルの「売上」ステップでも両方を示している）。

### 基準（`revenueBasis` / `netIncomeBasis`）の判断 → **設定しない**

- 5年とも米国会計原則で、会計基準の変更はない。
- 2025年4月1日のバンキング部門新設は**報告区分の変更**であって、連結の範囲や収益の定義の変更ではない。
  有報は「当連結会計期間の開示方法と整合させるために、過去に遡り報告数値の組み替えを行っております」と
  述べており、組み替えたのは**部門別の内訳**で、連結の収益合計・純利益は変わっていない
  （前期有報との比較で差異0件なのがその裏付け）。
- したがって perimeter change ではない。部門体制の変更は 2026年3月期の `note` に書いた。
- 各年度の `note` は、収益合計（金融費用控除後）の併記が主目的。2023年3月期だけ、収益合計が増えたのに
  収益合計（金融費用控除後）が減っている——差である金融費用が増えたため——という、読み違えやすい点を書いた。

## Gaps and judgement calls

### 1. **`verify-financials.mjs` が exit 1 で止まっている（ツール側の理由。データは曲げていない）**

数値はすべて一致している。出力は

```
nomura-holdings: 10 件の数値を有報XBRLと照合
前期有報との比較: 28 行一致（修正再表示なし）
利益・総資産・純資産・従業員数: 20 件を照合

不一致 5 件:
  - 2022年3月期 売上: ラベル「収益合計」は有報の売上・収益行の表記ではありません
  - 2023年3月期 売上: ラベル「収益合計」は有報の売上・収益行の表記ではありません
  - 2024年3月期 売上: ラベル「収益合計」は有報の売上・収益行の表記ではありません
  - 2025年3月期 売上: ラベル「収益合計」は有報の売上・収益行の表記ではありません
  - 2026年3月期 売上: ラベル「収益合計」は有報の売上・収益行の表記ではありません
```

金額の不一致は0件。引っかかっているのは `scripts/research/verify-financials.mjs` の

```js
/** A top line is 〜高 / 〜収益 / 〜収入 — never a profit row, never a truncation. */
const TOP_LINE_ENDING = /(高|収益|収入)$/;
```

だけである。野村の有報が印字する売上行のラベルは**「収益合計」**で、末尾が「計」なので
このルールを通らない。もう一方の候補「収益合計（金融費用控除後）」も末尾が「）」なので同じく通らない。
**この有報には、末尾が 高／収益／収入 になる収益行が存在しない。**

通すためにラベルを「収益」と書けば正規表現は通るが、それはこのルールのコメントが禁じている
「truncation（ラベルの切り詰め）」そのもので、有報の表記でもない。**データを曲げないほうを選び、止めた。**

エントリーの3ファイルは書き上げてあり、`npm run content:validate-file` は **exit 0** で通っている。
必要な対応は、米国会計基準採用会社の「〜合計」を受け付けるようルールを広げること（例：
`/(高|収益|収入|収益合計|収益合計（金融費用控除後）)$/` あるいは「収益」「収入」を**含む**かつ
利益・損失を含まない、という条件への変更）で、それはこの3ファイルの外側の変更なので手を付けていない。

### 2. セグメント情報のテキストブロックがない（タスクの指定事項）

上の「Segment ordering」に書いたとおり、**部門別の数値は `md-and-a.txt` から採った**。
注記23「セグメントおよび地域別情報」は取得できておらず、そこにある
（a）連結財務諸表数値と事業セグメント別数値の調整計算、（b）地域別の収益合計（金融費用控除後）と

### 3. 沿革の日付の並びについて（タスクの指定事項）

history.txt は**前半と後半で形式が違う**。

- 1925年12月から2011年5月までの各項目は、**年月がイベント文の直前にインラインで印字されている**。
  この範囲は沿革だけで成立している。
- 末尾で `2013年３月 / 2017年４月 / 2018年１月 / 2021年４月 / 2024年４月 / 2025年４月 / 2025年12月` の
  **7つの年月セルが先にまとまって出力され、そのあとに7つのイベント文が続く**形になっている。
  年の列とイベントの列が分離したずれ方である。
- **この有報には、その対応を裏付ける第二の記述がある。**
  - `md-and-a.txt`：「野村は、**2025年４月１日付でバンキング部門を新設**いたしました。これにより、
    野村の業務運営および経営成績の報告は、ウェルス・マネジメント部門、インベストメント・マネジメント部門、
    ホールセール部門、バンキング部門の区分で行われております。」
    → 7件目から2番目「バンキング部門を新設。」が **2025年４月** に対応することが確認できる。
  - `md-and-a.txt`：「**2025年12月**に買収を完了したMacquarie Group Limitedの米国および欧州における
    パブリック・アセットマネジメント事業」「**2025年12月１日**に買収が完了したマッコーリー・グループの
    パブリック・アセットマネジメント事業」
    → 最後のイベント（マッコーリーの事業取得・ノムラ・アセット・マネジメント・インターナショナル Inc.へ改称）が
    **2025年12月** に対応することが確認できる。
  - `affiliates.txt` に「ノムラ・アセット・マネジメント・インターナショナル Inc.（アメリカ、ウィルミントン市、
    持株会社、100％）」「デラウェア・マネジメント・カンパニー（投資顧問業、100％）」が載っており、
    買収が連結に反映されていることも確認できる。
- 末尾2件が固定され、7つの年月と7つのイベントが同数で、どちらも表の行順のまま昇順に出力されている以上、
  i 番目どうしが対応すると読める。この対応でエントリーに採録した。
  ただし 2013年3月・2017年4月・2018年1月・2021年4月・2024年4月 の5件については、
  **対応を直接述べる第二の記述は有報内に見つかっていない**。この点を明示しておく。
  なお 2021年4月のインベストメント・マネジメント部門設立は、現在の部門名と整合し、
  md-and-a が「ウェルス・マネジメント部門…2002年３月期の部門設立以来」「ホールセール部門…2010年４月の
  部門設立以来」と別の部門の設立年を述べていることとも矛盾しない。
