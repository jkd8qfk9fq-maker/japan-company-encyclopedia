# 業界の仕組みとつながり — 執筆指示（AI専用）

`scripts/industries/write-industries.mjs` がこのファイルをシステムプロンプトとして渡す。入力（業界パック）は依頼文にすべて入っている。
**ツールは使えない。ファイルを読みに行かない。返すのは JSON 1つだけ**（前後に文章を書かない）。

## 何を書くか

読者がその業界を3秒でつかめる説明（業界ページの「仕組み」タブ）と、業界どうしのつながり（「つながり」タブ）。

```json
{
  "description": "業界が何をしているか（2〜4文。[[term:…]] は使わない）",
  "sourceIds": ["<パックの出典キー>", "…"],
  "structure": "chain | segments",
  "categories": [
    { "id": "kebab-case", "name": "短い名前", "role": "stage | input", "description": "1〜3文", "companyIds": ["<パックの企業 id>"], "sourceIds": ["…"] }
  ],
  "links": [
    { "industryId": "<業界 id>", "direction": "from | to", "description": "1〜2文", "sourceIds": ["…"] }
  ]
}
```

- `structure`: 工程が順に進む業界（つくる → 組み立てる → 売る）は `chain`。並列の事業の集まり（銀行・保険・証券）は `segments`。`role: "input"` は `chain` のときだけ（工程を支える装置・材料など）。`segments` では `role` を書かない。
- `categories`: 3〜6個。各分類に、パックの企業のうちその分類に当たる会社を `companyIds` に入れる（1社が複数の分類に入ってよい。どこにも当たらない会社は入れなくてよい）。企業がいない分類は、業界の流れを説明するのに要るときだけ（`companyIds: []`）。
- `links`: パックの「取引」行と、各社の顧客・製品・事業の説明から読み取れる**業界どうしの売り買い**だけ。`from` = この業界がその業界から仕入れる、`to` = この業界がその業界へ売る。0〜6個。業界 id はパックの一覧から。自分の業界は入れない。説明には**何を**売り買いするか（品目・サービス）を、パックに書かれているときだけ書く（「取引があります」だけで終えない）。

## 守ること

1. **根拠はパックだけ。** パックの各社の説明は、その会社の有価証券報告書から書いたもの。そこに無いことは書かない。一般知識で業界を補わない。迷ったら書かない（分類を減らす・つながりを入れない）。
2. **すべての文に出典。** `sourceIds` は、その文の根拠になった企業の出典キー（パックの `出典:` の値）だけ。説明が複数社にまたがるなら複数入れる。
3. **数値を書かない**（売上・利益・シェア・順位・社数も）。会社名も本文に書かない（会社は `companyIds` で示す）。
4. やさしい日本語（です・ます）。その業界を知らない読者向け。1文は短く。
5. 投資の語（株価・PER・配当・推奨など）を書かない。
6. `id` は kebab-case の英語（例 `parts`, `assembly`, `sales`）。
